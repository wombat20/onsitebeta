마스터는 왼쪽 메뉴(페이지 목록 아래), 운영자는 운영보드 위와 **마이** 탭에 연결 상태가 표시돼요.

| 표시 | 뜻 |
|---|---|
| 실시간 연결됨 | 변경이 바로 오가요 |
| 연결됨 · 주기 동기화 | 실시간 연결이 막힌 네트워크예요. 3초마다 확인하니 그대로 써도 돼요 |
| 연결 끊김 · 이 기기에 임시 저장 (n건 대기) | 서버에 닿지 않아요(인터넷이 끊겼거나 서버 문제). 입력은 기기에 보관했다가 연결되면 자동으로 보내요. 새로고침하거나 로그아웃하지 마세요 |
| 다른 탭에서 사용 중 · 이 탭은 저장 안 됨 | 같은 계정이 이 기기의 다른 탭(창)에서 열려 있어요. 화면이 가려지고 이 탭에서는 기록할 수 없어요. 다른 탭을 닫으면 자동으로 이어서 쓸 수 있고, **이 탭에서 계속 쓰기**를 누르면 바로 가져와요 |

- 같은 계정은 한 기기에서 **탭 하나**로만 쓰세요. 마스터 두 명이 같은 PC를 쓴다면 크롬 프로필을 나누거나 한 명은 시크릿 창을 쓰세요(같은 브라우저에서 다른 계정으로 로그인하면 먼저 연 탭은 로그아웃돼요).

## 2. 마스터 첫 로그인

1. 마스터 주소를 열고 이메일과 **임시 비밀번호**로 로그인해요. 임시 비밀번호는 저장소나 코드에 없고, 작업 완료 보고(채팅)로만 전달됐어요.
2. 바로 새 비밀번호를 정하는 화면이 나와요. 영문과 숫자를 섞어 8자 이상으로 정해 주세요. (KFI26 마스터 두 계정은 2026-11-10에 비밀번호 변경을 마쳤어요.)
3. 마스터 계정은 두 개예요(채용 담당자, 비상 관리자 · 아이디는 각자의 이메일). 한쪽이 비밀번호를 잊으면 다른 쪽이 **운영자 초대 > 마스터 계정**에서 임시 비밀번호를 재발급할 수 있어요.

## 3. 면접 전날 준비 순서

1. **시간표** 메뉴에서 면접 시간표 엑셀(.xlsx)을 올려요(CSV도 돼요 · 한글 엑셀의 기본 CSV도 읽어요). 미리보기에서 인원·면접실·운영 시간과 **면접실별 회수(○회)** 가 계획과 같은지 확인하고 적용해요.
   - 노란 안내에 "조구분이 빈 칸인 n명은 … 같은 조로 넣었어요"가 보이면, 셀 병합된 조구분을 위 사람 조로 채운 거예요. 맞는지 확인해 주세요.
   - "같은 면접실에서 면접 시간이 겹쳐요"가 보이면 엑셀의 조구분·시각을 고친 뒤 다시 올려 주세요. 그대로 쓰면 뒤 면접이 자동으로 밀려서 입력하지 않은 지연처럼 보여요.
2. **운영자 초대** 메뉴에서 운영 인원마다 이름·역할(접수/인솔/상주)·연락처를 넣고 초대해요. 아이디(예: KFI26-S01)와 임시 비밀번호가 자동으로 만들어져요.
3. 초대 직후 나오는 **안내문 복사**를 눌러 카카오톡이나 문자로 보내요. 안내문에는 주소, 아이디, 임시 비밀번호만 들어 있어요(지원자 정보는 없어요).
4. 운영자가 휴대폰에서 첫 로그인하고 비밀번호를 바꾸면, 마스터 화면 상태가 **비밀번호 설정 완료**로 바뀌어요. 그 아래 **● 접속 중**은 최근 몇 분 안에 운영자 화면이 켜져 있었다는 뜻이에요(화면이 꺼진 휴대폰은 '최근 접속 시각'으로 보여요).
   - 카카오톡에서 링크를 누르면 카카오톡 안의 브라우저로 열려요. 거기서 로그인하면 다음에 크롬·사파리로 열 때 다시 로그인해야 해요. 로그인하기 전에 오른쪽 위 메뉴의 **다른 브라우저로 열기**로 크롬(안드로이드)이나 사파리(아이폰)에서 열고 로그인해 두세요(아이디는 그대로 채워져요).
   - **아이폰에서 홈 화면 아이콘으로 쓰려면:** 사파리에서 먼저 **홈 화면에 추가**를 하고, 그 **아이콘으로 열어서 로그인**하세요. 사파리에서 한 로그인은 홈 화면 아이콘에 이어지지 않아요. 그 뒤로는 아이콘만 쓰세요. (안드로이드 크롬의 바로가기는 크롬 로그인을 그대로 써요.)
   - 같은 계정을 한 휴대폰에서 탭 두 개로 열면 나중에 연 탭은 화면이 가려지고 기록할 수 없어요(1절 표 참고). 처음 탭을 쓰거나, 다른 탭을 닫으세요.
5. 연습으로 몇 건 기록해 본 뒤 **베타 관리 > 초기화**로 현장 기록을 지워요. 확인란에 `초기화`라고 입력해야 실행돼요(서버에 백업이 없어 되돌릴 수 없어요). 시간표와 계정은 그대로 남아요.
6. 운영자는 전날 미리 로그인해 두면 당일에 다시 로그인할 필요가 없어요. 한 장소에서 여러 명이 동시에 로그인을 반복하면 잠시 막힐 수 있어요(5분에 30회 수준).
7. 모든 휴대폰과 마스터 PC의 **날짜·시간을 자동 설정(네트워크 시간)** 으로 두세요. 같은 칸을 여러 기기에서 고쳤을 때 나중에 고친 값을 고르는 데 기기 시계를 써요.

### 현장에서 쓰는 기능 메모

- **성별 체크:** 운영자 휴대폰에서 지원자를 누르면 상세 화면 위쪽에 **성별(남/여)** 버튼이 있어요. 한 번 더 누르면 지워져요. 마스터 **현장 운영** 표의 '성별' 칸과 **현장 기록 내보내기** CSV에도 나와요(마스터 표에서도 바꿀 수 있어요).
- **면접 시간:** 운영자 명단의 조 머리와 지원자 상세에 `10:00–10:25`처럼 시작–종료가 함께 보여요(DELAY·불참이 반영된 실제 시각).
- **미도착 확인(자동 행동 강령):** 집결 시각 **5분 전**부터, 아직 접수되지 않은 지원자가 있는 조마다 "○면접실 · ○조 미도착 n명: 이름… · 연락 필요"(담당: 접수)가 행동 강령에 생겨요. 5분 전과 집결 정각에 운영자 휴대폰과 마스터 화면에 알림이 떠요. 접수(또는 불참 처리)하면 이름이 빠지고, 모두 도착하면 항목이 사라져요. 집결 시각이 지나도 남아 있으면 미완료(빨간색)로 보여요. 연락을 마쳤다면 체크해서 완료로 둘 수 있어요.

## 4. 면접 당일 점검표

- [ ] 마스터 PC 연결 상태가 "실시간 연결됨" 또는 "연결됨 · 주기 동기화"
- [ ] 운영자 전원에게 운영자 화면을 한 번 열어 달라고 한 뒤, **운영자 초대** 화면에서 모두 **● 접속 중**인지 확인 (아니면 그 운영자에게 화면을 다시 열거나 로그인해 달라고 요청)
- [ ] 접수 한 건을 운영자 폰에서 기록 → 마스터 화면에 반영되는지 확인
- [ ] 접수 담당 휴대폰에서 접수하면 전자기기 번호가 자동으로 붙는지 확인 (번호는 서버가 하나씩 배정해서 여러 명이 동시에 접수해도 겹치지 않아요)
- [ ] 중간중간 **베타 관리 > 현장 기록 내보내기**로 CSV 백업

## 5. 문제가 생겼을 때

| 상황 | 할 일 |
|---|---|
| 운영자가 비밀번호를 잊음 | 마스터가 운영자 초대 > **비밀번호 재발급** → 새 안내문 전달 |
| 운영자 휴대폰 분실·교체 | 해당 계정 **사용 중지** (바로 로그아웃돼요) → 새 휴대폰이면 재발급 후 다시 로그인 |
| 운영자를 빼야 함 | **사용 중지** 또는 **삭제** · 남긴 기록은 활동 로그에 그대로 있어요 |
| 마스터 비밀번호 분실 | 다른 마스터가 재발급 · 둘 다 잊었다면 아래 7절 SQL로 재설정 |
| 인터넷이 끊김 | 계속 입력해도 돼요. 기기에 보관했다가 연결되면 자동으로 보내요. 새로고침·로그아웃은 하지 마세요. 그사이 다른 기기에서 같은 칸을 더 나중에 고쳤다면 그 값이 남아요 |
| "초기화 전에 보내지 못한 기록 n건은 반영하지 않았어요" | 그 휴대폰이 오프라인일 때 마스터가 초기화를 했다는 뜻이에요. 초기화 전 기록이라 일부러 버린 거예요. 필요한 기록이면 다시 입력해 주세요 |
| 전자기기 번호에 "연결이 안 돼 이 기기에서 배정했어요 · 겹치는지 확인해 주세요" 안내가 뜸 | 연결이 끊긴 상태라 그 휴대폰이 번호를 정했어요(활동 로그에는 "오프라인 배정"으로 남아요). 다른 사람과 겹칠 수 있으니 마스터 화면에서 확인해 주세요 |
| 화면이 가려지고 "이 계정은 다른 탭(창)에서 열려 있어요"가 뜸 | 같은 계정이 그 기기의 다른 탭에서 열려 있어요. 다른 탭을 닫거나 **이 탭에서 계속 쓰기**를 누르세요 |
| 로그인 화면에 "이 브라우저의 다른 탭에서 다른 계정으로 로그인해서…"가 뜸 | 같은 브라우저에서 다른 계정으로 로그인했어요. 계정마다 브라우저 프로필(또는 시크릿 창)을 나눠 쓰세요 |
| "서버가 기록 1건을 받지 않았어요"가 뜸 | 권한 문제로 서버가 거부한 기록이에요. 화면을 새로고침한 뒤에도 반복되면 어떤 기록이었는지 적어 두고 마스터 화면에서 직접 입력해 주세요 |
| 화면에 "연결 끊김"이 계속 보임 | 화면이 열려 있다면 **그대로 계속 쓰세요.** 새로고침·로그아웃은 하지 마세요. 입력은 기기에 보관됐다가 연결되면 자동으로 보내져요 |
| Supabase 장애로 화면이 아예 안 열림 | 마지막 수단이에요. ① 마스터 PC에서 `beta-master.html?local=1` 로 열어요(로그인 화면에서 서버 연결에 실패하면 **비상용 로컬 모드로 열기** 버튼도 보여요) ② 이 PC에 남아 있는 **마지막 온라인 화면 가져오기**를 누르거나, 없으면 엑셀 시간표를 다시 올려요 ③ 이때부터는 **마스터 PC 한 대에서만** 기록해요(운영자 휴대폰의 로컬 기록은 마스터에게 오지 않아요) ④ 복구되면 원래 주소로 돌아가고, 비상 모드에서 적은 내용은 CSV를 보고 다시 입력해요 |

## 6. 면접이 끝난 뒤

1. **베타 관리 > 현장 기록 내보내기**, **로그 내보내기**로 CSV를 보관해요. 내보낸 CSV에는 지원자 정보가 있으니 기관 규정에 따라 보관·삭제해요.
2. 영구 삭제 전에 운영자 전원이 인터넷이 연결된 상태에서 **마이 > 로그아웃**을 눌러요. 로그아웃하면 그 휴대폰에 남은 시간표(지원자 이름·연락처)가 지워져요. 비상 로컬 모드를 썼던 마스터 PC는 브라우저의 사이트 데이터도 지워요.
3. **베타 관리 > 행사 데이터 영구 삭제**를 눌러 지원자 명단, 현장 기록, 로그, 운영자 계정을 지워요. 마스터 계정만 남아요.
4. 무료 플랜 Supabase 프로젝트는 7일 동안 사용이 없으면 자동으로 일시정지돼요(90일 안에 대시보드에서 다시 켤 수 있어요). 더 쓰지 않으면 그대로 두거나 대시보드에서 프로젝트를 삭제해요.

- 데이터 보호: 모든 테이블에 RLS. 로그인한 행사 멤버만 읽고 쓸 수 있어요. 첫 비밀번호 변경 전 계정과 사용 중지된 계정은 아무것도 볼 수 없어요. 공개 키로 회원가입하는 것은 막혀 있어요. 계정 관리·초기화·삭제는 서버 함수 `admin-ops`에서만 해요.
- 코드에 들어 있는 Supabase 주소와 `sb_publishable_` 키는 원래 공개용이에요. 관리자 키(secret/service_role)는 서버 함수 안에만 있어요.

### 마스터 비밀번호를 둘 다 잊었을 때 (Supabase 대시보드 > SQL Editor)

```sql
-- 새 임시 비밀번호로 바꾸고, 사용 중지도 풀고, 다음 로그인 때 변경하도록 표시
update auth.users set encrypted_password = extensions.crypt('여기에-새-임시비번-12자', extensions.gen_salt('bf')),
       banned_until = null, updated_at = now()
 where email = '마스터-이메일@example.com';
update public.members set must_change = true, disabled = false where login_id = '마스터-이메일@example.com';
delete from auth.sessions where user_id = (select id from auth.users where email = '마스터-이메일@example.com');
```

### 선택: 비밀번호 규칙을 서버에서도 강제하기

앱은 영문·숫자 포함 8자 이상만 받지만, Supabase 기본 설정은 6자 이상이에요. 대시보드 **Authentication > Providers > Email**(또는 Password Security)에서 최소 길이 8, 문자 종류(영문+숫자)를 켜 두면 어떤 경로로도 약한 비밀번호를 쓸 수 없어요. 유출된 비밀번호 차단은 유료 플랜 기능이에요.
